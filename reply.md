Fixed in f31c8af5 — reap is now registered immediately after every successful `cmd.Start()`, before any readiness wait, so every early-return path (timeout, `require` failure, `t.Fatalf`) still terminates and reaps the child.

- `registerOrphanReaper` now guards against a nil `Process` and documents why both calls go through the `os.Process` handle rather than a raw `syscall.Kill(pid|-pid, ...)`: `os.Process` refuses to signal once it has been waited on, which makes the cleanup idempotent with each test's own `waitDone`-synchronized shutdown *and* incapable of signaling an unrelated process that recycled the pid. The `Wait` is what actually reaps — kill-without-wait would just leave a zombie for the lifetime of the test binary.
- The three remaining raw spawn sites in this file (`TestSoftKillProcess_AlreadyDeadIsNoop`, `TestReapWithEOFGrace_AlreadyDeadIsNoop`, `TestSoftKillProcessGroup_AlreadyDeadIsNoop`) are covered too — each has a `require` between `Start` and `Wait` that can abort the test before the reap.
- `spawnHelperWithStdinPipe` additionally closes the parent's write end on cleanup: `cmd.Wait()` is never called, so nothing else closes it, and an early return would leak the fd while denying the child the EOF it is waiting for.
- Same pattern applied to the other helper-spawn site the PR touches, `cmd/agent-deck/cgroup_isolation_wiring_test.go`: the unbounded SIGTERM-then-Wait defer is now a `t.Cleanup` registered right after `Start` that escalates to SIGKILL after a 5s grace, so a TUI that declines to exit on TERM can no longer hang the wait with the subprocess still alive. The signal is sent before the waiter goroutine starts and the SIGKILL is only reached while `Wait` provably has not returned, so no pgid can be recycled under us.
