## The three script corrections this drive forced

G0 reserves the right to be corrected by a real frame, never by relaxing an
assertion. Three corrections landed.

**1. The unknown-window sentence moved, so the assertion was re-pointed and
widened.** Step 04 asserted the literal string `context window size unknown, so
no percentage is shown`. The screen now reads `no percentage: <reason>` followed
by `To get one, set AGENTDECK_CONTEXT_WINDOW…`. The substring was stale, not the
software. The assertion now accepts a percentage **or** `no percentage: `, and a
**second** assertion requires a percentage **or** the literal
`AGENTDECK_CONTEXT_WINDOW` on the same frame — so an honest unknown that is also
a dead end now fails the gate, which the single old substring never checked.

**2. The Verify tab is now captured (step `11-verify-tab`).** The Overview tells
the reader "press 3 for Verify" and no frame had ever recorded what that key
does. It is also where two provider-measured figures went when info-severity
caveats were demoted — see the G4 failure below.

**3. Driver B's "unknown model" world had silently stopped being one.**
`tools/sixgate/driveb.go` pinned the row to `claude-opus-5` with a comment
saying the window table "stops at claude-opus-4-7". The table has since been
taught the whole 5-series, so from that commit the row recorded a **taught**
screen — header `window 1.0M tokens (model-default)`, live percentage — under a
fixture named `claude-unknown-model`, and passed, because step 04's assertion
accepts a percentage *or* the unknown sentence and cannot tell which world it is
in. The row's own doc comment had predicted this exact rot and it happened
anyway. It is now pinned to the bare alias `opus`, which is not hypothetical:
two live sessions on the maintainer's deck (`stream-fub-visibility`,

## Why G4 fails

`claude-cold-provider-usage` is the only oracle with numbers somebody else
produced. Two of its three figures now grade `ours-missing`:

| figure | oracle | on screen |
|---|---|---|
| `window_used_tokens` | 27008 | `27.0k` — **agree** (±50) |
| `anchor_measured_tokens` | 27008 | **absent from every captured frame** |
| `cache_read_tokens` | 3000 | **absent from every captured frame** |

Both used to be legible in an info caveat on the Overview
(`3000 of the measured 27008 prompt tokens were served from Anthropic's prompt
cache…`). Demoting info-severity caveats collapsed that caveat behind
"2 further caveats worth knowing — press 3 for Verify", and the Verify tab
prints the anchor humanized (`27.0k`) with the exact arithmetic truncated inside
the `HOW` column. The exact figure the report calls **measured** is therefore no
longer stated in full anywhere the journey can see.

Nothing on screen is false — this is a legibility regression, not a lie — but
the consequence is precise and is the reason the gate is red: the one number the
feature labels *measured* can no longer be checked against the provider's own
accounting, and a `measured` label nobody can verify is exactly what G4 exists
to prevent. **The oracle declaration was deliberately left untouched.** Tuning
the probe or widening the tolerance until it passes would remove the gate's
ability to notice, which is the failure mode the framework was built against.
The fix belongs to whoever owns the caveat demotion: put the exact anchor and
its cache split back within reach of a captured frame, then re-run
`sixgate oracle compare` and `sixgate assert`.

### The model is still lost on those four sessions

`readFirstTurn`'s pre-block path was fixed; the **boundary** path was not.
`consumeAssistant` (`internal/ctxinspect/claude/transcript.go:445`) reads the
first assistant record after the startup burst, and returns `stop = true`
unconditionally — even when that record yielded no usable turn and there was no
earlier one to fall back to. On these transcripts the boundary record is a
`<synthetic>` placeholder with `usage.input_tokens: 0`, so the parse stops on it
and never reaches the 215 `claude-fable-5` records behind it.

What the reader now says is true — *"1 assistant record(s) were read and none of
them carries provider accounting agent-deck can use … whether this session has
completed a model turn is not knowable from them"* — which is the difference
between an honest unknown and the fabricated one this pass set out to remove.
But the model is still thrown away, so `ResolveWindow` still takes its
`id == ""` branch and the user still gets the weaker remedy ("set
AGENTDECK_CONTEXT_WINDOW") instead of the window `claude-fable-5` would have
resolved to.
